# BUILD: ComfyUI provider (owner, 2026-10-23, as sent; supersedes
# 2026-10-23-comfyui-original.md)

Runs on a friend's high-end workstation (big GPU, already runs Krea 2),
reached through a private tunnel. Not RunPod, not a hosted service. The
machine is not connected yet: build and test against a mock ComfyUI
server; the setup guide (item 13) is how the owner connects it.

Goal: the Studio sends stills, edits and video jobs to ComfyUI on a
powerful remote machine, as one more provider in config/engines.yaml next
to Higgsfield, Google, Kie.ai and WaveSpeed. Full-size models; no low-VRAM
workarounds.

CONNECTION
1. Settings > Provider keys > ComfyUI: base URL plus access token
   (dashboard only, never in repo), through a private tunnel (Cloudflare
   Tunnel or Tailscale), never an open port.
2. Status card: online/offline, GPU name and VRAM, queue length, models
   found. "Test connection".
3. Talks to the ComfyUI API: upload images, queue prompt, websocket
   progress, fetch outputs to R2.

ENGINE
E1. Gateway and queue: the Railway worker is the gateway; it validates each
    job, puts it on a persistent queue, returns a job ID. A small agent on
    the GPU machine pulls jobs; the machine never takes calls from the app.
E2. Jobs are never lost: a claimed job that goes quiet past its timeout is
    reclaimed and retried once, then lands in a Failed list Eric can retry.
    Every job has an idempotency key (row_id + step + attempt): no double
    posts.
E3. Frozen environment: a pinned Docker image (ComfyUI commit, every custom
    node at a commit hash, Python packages, CUDA) plus a model manifest with
    checksums, in /comfy/env. The agent reports its environment hash; the
    Studio refuses jobs on a mismatch and says why.
E4. Group jobs by model family (Krea 2, then Qwen, then Wan). Models stay on
    local disk. The agent reports ready only after the model loads.
E5. Recipe log: workflow version, model and LoRA versions, seed, prompt,
    refs on every output. "Remake exactly."
E6. Crash handling: agent restarts itself; out-of-memory retries once at a
    smaller batch; stuck jobs are killed at a hard timeout.
E7. Health: queue depth, GPU use, VRAM, time per job type, failure rate on
    the status card; alert if the machine goes offline mid-batch.

WORKFLOWS
4. API-format JSON in /comfy/workflows, each with a manifest: name, step
   type (still, edit, i2v, recreate), inputs (prompt, refs, seed, LoRA,
   strength, size, frames), outputs. Eric can upload a new workflow in
   Settings, no rebuild.
5. Ship first: a. Still/edit: Qwen-Image-Edit-2511 with the character's
   LoRA plus refs. b. Image-to-video: Wan 2.2 I2V. c. Recreate: Wan 2.2
   Animate (replace and mix). d. Still: Krea 2 Turbo with a LoRA trained on
   Krea 2 Raw (text-to-image, face from the LoRA), marked "license check"
   until Eric confirms commercial use.

CHARACTER LORAS
6. "Train LoRA" on any person character: pick the base (Qwen or Krea 2
   Raw), uses REF-00 to REF-11 (plus 12/13) and any approved stills Eric
   ticks. Runs on the machine, shows estimated time, saves version and
   trigger word. Retrain makes v2; old versions selectable.
7. Faceless characters skip LoRAs.

RULES INSIDE THE PIPELINE
8. 21+ only, non-explicit (prompt lint before queueing), adult check on
   source clips, AI label on export, realism block on person shots.

COST AND SAFETY
9. Every job waits for Eric's click. Show "$0 API, about N min on ComfyUI."
10. Machine offline: the step says so and offers the next provider with its
    price. Never switch silently.
11. Owner's own work is never blocked: max-jobs-at-once setting, and he can
    pause the queue.

FIRST JOB: CALLIE BAKE-OFF
12. "Compare providers": 10 of Callie's real prompts on Nano Banana
    (Kie.ai), Qwen and Krea 2 Turbo (her LoRAs), side by side in Review,
    with face score vs REF-00 and a skin smoothness score. Eric picks
    defaults per step.

SETUP GUIDE
13. docs/COMFY.md for the machine owner: run the pinned Docker image, model
    downloads with checksums, tunnel, agent token, pausing the queue.

SHARED OUTPUT FORMAT
14. docs/DRIVE-OUTPUT.md: the Drive output (folders plus manifest, Device
    ID and Account first). Nothing tied to Eric: each install sets its own
    Drive, accounts, devices.

ENGINE LEVER
15. One switch at the top of Settings and on Weeks: Engine = Higgsfield
    subscription, Higgsfield API, Kie.ai, WaveSpeed or ComfyUI. The table
    picks each step's model, prices switch units (credits, dollars, machine
    minutes), a step the engine can't do says so and offers the closest
    with its price, per character and per step overrides, engine saved in
    the recipe log.

FINISH: tests pass (mock ComfyUI server: a killed job is reclaimed, a retry
doesn't double post, an environment mismatch is refused). Push. Confirm the
deploy is READY and the version. Update the guide and help buttons. Report
item by item.
